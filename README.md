# FLTK.jl

[![CI](https://github.com/pjabardo/FLTK.jl/actions/workflows/CI.yml/badge.svg)](https://github.com/pjabardo/FLTK.jl/actions/workflows/CI.yml)

Julia bindings for [FLTK 1.4](https://www.fltk.org), the Fast Light Toolkit.

```julia
using FLTK

win = Window(340, 180, "Hello") do win
    Box(20, 20, 300, 60, "Hello, World!"; box = FL_UP_BOX, labelsize = 28)
    Button(120, 110, 100, 40, "Click me") do b
        fl_message("Hello from Julia!")
    end
end
show!(win)
fl_run()
```

## How it works

```
Julia (src/*.jl)  ──ccall──▶  libfltkjl.so (deps/fltkjl/fltkjl.cpp)  ──▶  libfltk.so
       ▲                               │
       └──── @cfunction hooks ─────────┘   callbacks, draw(), handle(), destructor
```

* **C shim.** `deps/fltkjl/fltkjl.cpp` exposes FLTK's C++ API as plain
  `extern "C"` functions. No CxxWrap is needed.
* **Julia-aware subclasses.** Every widget created from Julia is a
  `JlW<Fl_Xxx>` subclass. It forwards `draw()` and `handle()` to Julia when
  you override them, and its destructor tells Julia the widget is gone.
* **Ownership stays with FLTK.** As in C++, a group deletes its children.
  When a widget is deleted, its Julia handle is invalidated: using it
  raises an `ArgumentError` instead of crashing.
* **Constants come from the headers.** `src/constants.jl` is generated by
  `deps/fltkjl/gen_constants.cpp`, so every `FL_*` value matches the FLTK
  you build against.

## Building

You need FLTK 1.4 built with shared libraries (`-D FLTK_BUILD_SHARED_LIBS=ON`).
The build uses `fltk-config` to find it, by default `../build/fltk-config`
(the FLTK build next to this package).

```bash
make -C deps                                   # default FLTK location
make -C deps FLTK_CONFIG=/usr/local/bin/fltk-config
```

or from Julia: `ENV["FLTK_CONFIG"] = "..."; Pkg.build("FLTK")`.

Run the tests (they open windows briefly):

```bash
julia --project=. test/runtests.jl
```

## Guide

### Creating widgets

Constructors mirror FLTK: `Type(x, y, w, h, label = ""; properties...)`.
Any property can be passed as a keyword:

```julia
s = HorValueSlider(10, 10, 200, 25, "Volume"; range = (0, 11), step = 1, value = 5,
                   callback = s -> println(value(s)))
```

A **do-block** has two meanings:

* on a **group or window**, it fills the group: widgets created inside become
  its children;
* on any **other widget**, it sets the callback.

Groups are closed when their constructor returns. Widgets created afterwards
are not silently added to them. To add more children later, use
`add!(group, widget)` or `begin_group(g)` … `end_group(g)`.

### Properties and functions

Each property has a getter, a setter and property syntax:

```julia
label(b);  label!(b, "OK");  b.label = "OK"
value(s);  value!(s, 3.0);   s.value = 3.0
b.color = FL_RED;  b.box = FL_ROUND_UP_BOX;  b.tooltip = "Press me"
```

Geometry: `bounds(w)` returns `(x, y, w, h)`, `w.x`, `w.w`, `resize!(w, x, y, w, h)`,
`position!`, `size!`. Groups support `length(g)`, `g[i]`, iteration and `parent(w)`.

Indices follow FLTK. Browser lines are 1-based. Menu item indices and
Grid rows/columns are 0-based.

### Event loop

| function | use |
|---|---|
| `fl_run()` | Runs until all windows close. Other Julia tasks keep running, with ~10 ms latency. |
| `fl_run_blocking()` | Plain `Fl::run()`. Zero idle CPU, but other Julia tasks do not run. |
| `start_eventloop()` / `stop_eventloop()` | Interactive REPL use: windows stay live while you type. |
| `fl_wait(t)`, `fl_check()` | Manual stepping. |
| `add_timeout(f, secs; repeat=false)`, `remove_timeout(id)` | FLTK timers. |

FLTK is single-threaded: call it only from the thread that runs the event loop.

### Custom drawing and events

```julia
canvas = Box(0, 0, 400, 300)
draw!(canvas) do c
    fl_rectf(c.x, c.y, c.w, c.h, FL_BLACK)
    fl_color(FL_YELLOW)
    fl_begin_polygon(); fl_circle(c.x + 200, c.y + 150, 50); fl_end_polygon()
end
handle!(canvas) do c, ev
    ev == FL_PUSH ? (println("click at ", event_x(), ",", event_y()); true) : nothing
end
```

A `handle!` function returns `true`/`false`, or `nothing` to fall back to
the widget's default handling. Use `super_draw(w)` and `super_handle(w, ev)`
to call the defaults explicitly. Drawing functions keep their C++ names:
`fl_color`, `fl_rectf`, `fl_line`, `fl_draw`, `fl_font`, `fl_push_clip`,
`fl_begin_line`/`fl_vertex`, and so on. `fl_polyline(xs, ys)` and
`fl_draw_image(pixels, x, y)` take Julia arrays. An exception inside a
callback is logged and does not crash the program.

### What's wrapped

| area | Julia types / functions |
|---|---|
| windows | `Window`, `DoubleWindow`, `GlWindow` |
| containers | `Group`, `Tabs`, `Scroll`, `Pack`, `Tile`, `Flex`, `Grid`, `Wizard` |
| buttons | `Button`, `LightButton`, `CheckButton`, `RoundButton`, `RadioButton`, `RadioRoundButton`, `RadioLightButton`, `ToggleButton`, `ReturnButton`, `RepeatButton` |
| text input | `Input`, `IntInput`, `FloatInput`, `SecretInput`, `MultilineInput`, `Output`, `MultilineOutput` |
| valuators | `Slider`, `HorSlider`, `NiceSlider`, `HorNiceSlider`, `FillSlider`, `ValueSlider`, `HorValueSlider`, `Scrollbar`, `Dial`, `Roller`, `Counter`, `Adjuster`, `ValueInput`, `ValueOutput`, `Spinner`, `Progress` |
| menus | `MenuBar`, `MenuButton`, `Choice` (`add_item!` with per-item callbacks, shortcuts, toggle/radio items) |
| lists | `Browser`, `HoldBrowser`, `SelectBrowser`, `MultiBrowser`, `CheckBrowser`, `Tree` |
| text | `TextBuffer`, `TextView` (`Fl_Text_Display`), `TextEditor`, `Terminal` |
| other | `Box`, `Clock`, images (`load_image`, `RGBImage`), dialogs (`fl_message`, `fl_alert`, `fl_choice`, `fl_input`, `fl_password`, `fl_color_chooser`, `fl_file_chooser`, `native_file_chooser`), screens, colors, fonts, clipboard |

`TextView` is Julia's name for `Fl_Text_Display`, because `Base.TextDisplay`
already exists.

## Not yet wrapped

`Fl_Table` (needs a `draw_cell` override), offscreen drawing and image
surfaces, printing, `Fl_Preferences`, drag and drop / paste
(`FL_PASTE` events arrive, but `Fl::paste` is not wrapped), text styling
in `Fl_Text_Display`, and threading helpers (`Fl::lock`/`Fl::awake` are in
the shim, but nothing on the Julia side uses them yet).
